what is built (architecture)

Two programs turn three raw data sources into four result files plus two human-readable docs. etl_ambulance.py unpacks the fire spreadsheets; service_ambulance.py builds the demand map, station list and answer key, then runs the two experiments. Everything follows the shared team contract (British National Grid metres · 1km cells · all times in seconds).

bugs & errors encountered (and fixed)
  • GB10 reports GPU utilization as N/A. First run flagged Test 1 as FAILED because nvidia-smi returned no utilization on the unified-memory GB10. Fix: read the trained booster's device config (cuda:0) instead. A measurement quirk, not a real failure.
  • Spark Python env had no pip. The optional libs (fastexcel, pyproj) never installed, so reading the spreadsheets crashed — cascading into Tests 4/5/6. Fix: bootstrapped pip via ensurepip, installed, re-ran. All green.
  • Cosmetic XGBoost warning. "input data on cpu while booster on cuda:0" during prediction — harmless, results unaffected.
what is needed next (improvements)
  • Close the p90 tail gap. The sim matches the average within ~13% but undershoots the worst-case (p90) by ~33%. It's free-flow: it assumes the nearest ambulance is always free. Modelling queueing / crew-unavailability / hospital handover would close most of that tail — and the gap itself quantifies that friction.
  • Validate the demand proxy. Demand is inferred from fire door-forcing + car crashes, not real ambulance locations (not public). Cross-check against the GLA Ward Atlas ambulance call-outs to show it correlates with something independent.
  • Widen the turnout prior. Activation time is sampled from per-station medians, understating real variability. Using the full call-by-call spread makes the tail estimate more honest.
  • Exploit the GPU at scale. At this size GPU≈CPU. To use the GB10's power, scale up: GPU-accelerate the closure sweep, run a hyper-parameter search, or train the quantile models.
  • Verify the station list. 73 stations auto-pulled from OpenStreetMap + lightly filtered — reconcile against the official ~70 LAS list.
  • Test the demand weighting. Door-forcing and crashes are weighted 1:1 — run a sensitivity check that station rankings don't swing under other weightings.
bottom line

The ambulance pipeline runs end-to-end on the DGX Spark, trains the travel model on the GB10 GPU with no loss of accuracy (medAE 43.8s), reproduces results exactly, and is fast (~2.4s for a 50k-call sim + 73-station sweep). Honest caveats: the GPU gives no speed advantage at this scale (its value is data-locality), and the sim matches the average response (-12.7%) but undershoots the worst-case tail (-33%) because it doesn't yet model queueing — the top priority next.
